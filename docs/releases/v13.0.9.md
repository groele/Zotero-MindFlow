## 🌟 核心检验、问题诊断与优化细节

### 1. 独立窗口特权消息响应打通（Standalone Workspace Window Privileged Message Routing）
- **问题诊断**：MindFlow 允许在独立 OS 窗口（`openStandaloneWorkspaceWindow`）运行导图工作台。在 `chrome/content/scripts/index.js` 的 `handleHostMessage` 中，原实现只用 `doc.querySelectorAll('.mindflow-workspace-iframe')` 校验来源 frame，而独立窗口不在主窗口 DOM 树中，导致独立窗口发送的 `MINDFLOW_LOCATE_ITEM`、`MINDFLOW_OPEN_PDF`、`MINDFLOW_LAUNCH_URL`、`MINDFLOW_NOTIFY` 等特权消息被鉴权过滤、完全静默丢失；
- **优化实现**：将来源鉴权拓展为 `const isOwner = Boolean(ownerFrame) || this.ownsWorkspaceWindow(source); if (!isOwner) return;`，使独立窗口与内置标签页具备完全一致、受信任的宿主联动响应能力。

### 2. 文献跨集合自动切换展开与窗口聚焦（Item Selection Collection Navigation & Window Focus）
- **问题诊断**：原 `MINDFLOW_LOCATE_ITEM` 及 `zoteroBridge.ts:locateItemInZotero` 仅执行 `pane.selectItem(item.id)`，当用户在左侧分类树选在其他非父级集合时，Zotero 不会自动切换到该文献所在集合，导致中间文献列表呈现空白或不显示该条目，且在独立窗口操作后主窗口未能自动置顶聚焦；
- **优化实现**：更新为 `pane.selectItem(item.id, true)`，强制 Zotero 自动展开并选中条目所属集合，并补充 `mainWin?.focus?.()`，确保在任何视图下定位文献都能即时显式呈现。

### 3. 内存兜底 DOI 搜索附件父条目递归解析（In-Memory DOI Fallback Attachment Parent Resolution）
- **问题诊断**：在通过内存索引兜底搜索 DOI（`Zotero.Items.getAll(libID)`）时，若文献条目的 PDF 附件元数据或 Extra 中也包含该 DOI，原逻辑直接返回了该 attachment 附件条目，导致后续题录信息提取、元数据展示或定位异常；
- **优化实现**：在宿主 `index.js` 与前端 `zoteroBridge.ts` 中同步加入 `item.isRegularItem()` 与 `item.parentItemID` 判定，若命中附件条目则自动递归解析并返回其父级文献题录条目。

### 4. 属性栏文献定位优先级倒置修复（Property Sidebar Target Priority Inversion Resolution）
- **问题诊断**：在 `PropertySidebar.tsx` 中，原逻辑优先使用整张导图的绑定文献 `currentDoc.metadata?.zoteroItemKey`，之后才检查选中节点的 DOI。当整张导图挂靠在文献 A 下、但某个分支节点明确标注了文献 B 的 DOI 时，点击右侧属性栏的“文库定位”或“打开 PDF”会错误跳到文献 A；
- **优化实现**：修正为节点优先策略（优先判定 `selectedNode.link` 或 `nodeDoi`），仅在节点本身没有文献信息时才回退至导图根文档绑定文献。

### 5. 右键菜单文献定位协议解析对齐（Context Menu Target URI Resolution Priority）
- **问题诊断**：在 `ContextMenu.tsx` 中，如果节点同时存在外部超链接和提取出的 DOI，原逻辑可能直接将泛化外部链接透传，导致错失本地 Zotero 条目直达能力；
- **优化实现**：强化优先级判定，优先以已解析的文献 DOI / Zotero URI 唤起原生文库定位与 PDF 阅读，确保科研工作流直达。

### 6. 外链协议安全白名单与环境嗅探增强（URL Protocol Security & Environment Sniffing）
- 宿主 `MINDFLOW_LAUNCH_URL` 消息处理增加 `/^(https?|zotero):\/\//i` 协议白名单过滤，防止恶意调用；
- 优化前端 `zoteroBridge.ts:isZoteroEnvironment()`，兼容 `isZoteroWorkspace()` 标志，防止在独立窗口模式下误降级为纯浏览器环境。
