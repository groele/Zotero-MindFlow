# Zotero MindFlow 14.0.7

架构债务清零版本：8 个前端巨型 React 组件完成真实模块化拆分，`freeze-and-shrink` 冻结基线自本版起清空。兼容声明 Zotero 10.0 – 12.*（开发基准 Zotero 10；11/12 为前瞻声明，未做实机验证）。

### 拆分原则：真实 ES 模块，不是文本分片

- 前端 TSX 全部拆为**真正的 ES 模块**：`import` / `export` + 运行时函数调用组合。不是编译期文本分片、不是构建期拼接、不是生成产物，因此不会把上一轮刚消除的「双轨」重新带回来。
- 采用 **Context Object + Destructure**：连续 handler / effect 块抽成自定义 hook，hook 接收 ctx 并在开头解构出与原代码同名的变量，使块内代码逐字保留；主编排 hook 按原顺序依次调用并合并 ctx。大段 JSX 抽成子组件，props 传 ctx 后在组件内解构。主组件用一次解构还原全部裸变量名，主 JSX 因此无需改写。
- 公开导出名、props 形状、用户可见文案、CSS class、事件绑定、state 语义、hooks 调用顺序与 `useCallback` / `useEffect` 依赖数组全部保持不变；所有新模块 ≤360 行。
- 新增可复现的等价验证脚本，比对拆分前后的用户可见文案、类名 token 与事件/data 标记，任何增删都按行为回归处理。

### 治理：守卫支持「债务清零」

- `architecture-guard.mjs` 的基线完整性检查原本强制 `oversized` 非空；全部冻结模块拆完后该断言会误报。现改为：仅当 `architecture-baseline.json` 显式声明 `"debtCleared": true` 时允许空基线，且声明清零后不得残留任何条目；未声明的空基线仍被拒绝。
- 第一项 §5.9 守卫始终拒绝任何新的 >360 行源文件，**清空基线不等于关闭门禁**。`AGENTS.md` 已补写该规则。
- `splitHistory` 追加 14.0.7 拆分记录，`lastReleasedVersion` 在发布时更新为本版。

### 版本与发布链路校正

- **14.0.6 是本地未推送的中间版本**（架构收口 + 宿主入口 18 分片），从未创建 GitHub Release；线上 Latest 一直是 14.0.5。本版直接把 14.0.5 演进到 14.0.7。
- 开发轮次把两份 `update.json` 回退到线上真实在服务的 14.0.5，避免把本地未发布元数据误当作线上版本；正式打包时再切到 14.0.7 并回填 `sha512:` 全量哈希。

## 已知边界

- **真实 Zotero 宿主安装、亮暗主题与窄窗 computed style、Zotero 11/12 实机、多窗口回归仍未执行**。按项目六层验证口径，静态分析 / 单测 / 构建 / 发布配置不替代原生验收。
- 前端子项目现有 5 个 `vite-node` 逻辑测试脚本，**没有组件渲染测试**；本次拆分由双端 TypeScript 严格检查（`noUnusedLocals` / `noUnusedParameters`）、Vite 生产构建与文案/类名等价比对共同兜底，但不等于真实浏览器回归。
- 宿主入口仍是 `src/host/entry/` 下 18 个**编译期文本单元**，不是独立 ESM 模块；把它升级为真正的模块化运行时仍以真实 Zotero 宿主验收为前置条件。

## 安装

从本 Release 下载 `zotero-mindflow-14.0.7.xpi`，在 Zotero 的「工具 → 插件」中通过齿轮菜单选择「从文件安装插件...」，或直接将 XPI 拖入窗口后重启。已安装旧版本的用户可通过自动更新获取。

校验和见仓库根目录 `SHA256SUMS.txt` / `SHA512SUMS.txt` 与 `docs/package-verification.json`。
