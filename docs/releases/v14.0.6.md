# Zotero MindFlow 14.0.6

架构迁移收口版本：宿主运行时完成「单一权威源」改造，并把治理门禁接入 CI。兼容声明 Zotero 10.0 – 12.*（开发基准 Zotero 10；11/12 为前瞻声明，未做实机验证）。

## 本版改动

### 架构迁移：消除双轨

- `src/` 成为宿主侧**唯一权威源**。`chrome/content/scripts/` 下的 9 个运行时脚本（宿主入口 `index.js`、设置面板 `preferences.js`、7 个领域模块）**全部由 TypeScript 生成**，首行带 `// [Generated … DO NOT EDIT DIRECTLY]` 溯源横幅，禁止手改。
- 新增 `scripts/host-build-targets.mjs` 作为生成规则的唯一定义；构建脚本 `build-source.mjs [4/7]` 与架构守卫共用同一份配方，杜绝两边各写一套。
- 新增 `src/host/index.ts`（4,484 行）作为宿主入口权威源。因 `bootstrap.js` 以 `loadSubScript` 载入自定义作用域、宿主测试夹具依赖其中的字面量钩子，入口按原文逐字渲染（仅剥离两行编译期标记），**正文与历史入口逐字节一致，行为零变化**。
- `AGENTS.md` 新增《单一权威源与生成产物》一节，明确产物禁手改、横幅与清单登记要求、入口豁免范围。

### 治理：守卫 11 → 15 项，并接入 CI

- 新增「生成产物清单与横幅齐备」「用同一配方重渲染并逐字节比对」两项，手改产物或改了 TS 忘了重建都会被拦截（已做负向验证：注入一行改动后守卫 EXIT=1）。
- 新增「宿主入口消费的全局名 ↔ 产物挂载名一一对应」「设置面板必须挂在 `window`」「原生测试注入锚点保留」「`@ts-nocheck` 只允许历史入口」四项。
- `release-integrity.yml` 现在以 `npm ci` 锁定 esbuild 0.28.2 / vite 8.3.0，运行双端类型检查、15 项守卫、前端单测、宿主模拟测试与包校验；打包步骤按 `releaseStatus` 自动选择正式/候选模式，修复了开发轮次 CI 误报红灯。

### 结构债务：冻结模块 11 → 9

- `layoutEngine.ts` 568 → 95 行，拆为 `layoutMetrics` / `layoutHorizontal` / `layoutMindmap` / `layoutStructured`。
- `treeOps.ts` 429 → 8 行转发门面，拆为 `treeCore` / `treeStructure` / `treeText`；先抽基础层化解了历史循环依赖。全部公开 API 零变化。

### 修复

- 设置面板恢复 Zotero 10 pane sandbox 契约：`init()` 必须挂在 preferences window，去掉会静默挂错对象的 `globalThis` 回退。
- 清理版本字段批量替换引入的 CRLF、5 处文件末尾空行；`git diff --check` 归零。
- README / 设置页发布入口从过期的 v14.0.1 修正到真实发布版本。

## 已知边界

- **真实 Zotero 宿主安装、亮暗主题与窄窗 computed style、Zotero 11/12 实机、多窗口回归未执行**。按项目六层验证口径，静态分析 / 单测 / 构建 / 发布 / 更新源配置不替代原生验收；本次发布是在该层缺口已知的前提下执行的。
- `src/host/index.ts` 仍是 4,484 行冻结模块（单是 `Zotero.MindFlow = {…}` 对象就约 3,750 行）。双轨已消除，但入口尚未模块化；真正拆分等于重写主运行时，需先具备真实宿主验收条件。
- 另有 8 个前端冻结模块（`App.tsx`、`SettingsModal.tsx`、`Toolbar.tsx` 等）受基线禁增长约束。

## 安装

从本 Release 下载 `zotero-mindflow-14.0.6.xpi`，在 Zotero 的「工具 → 插件」中通过齿轮菜单选择「从文件安装插件...」，或直接将 XPI 拖入窗口后重启。已安装旧版本的用户可通过自动更新获取。

校验和见仓库根目录 `SHA256SUMS.txt` / `SHA512SUMS.txt` 与 `docs/package-verification.json`。
